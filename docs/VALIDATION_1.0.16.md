# 1.0.16 升级兼容与一次性恢复

> 后续现场补充（2026-11-26）：SentinelOne 截图已经确认暂存目录中的更新组件被隔离。下面保留的是当时的本机测试与操作记录，不是目前对公司环境的放行承诺。遇到安全软件告警时停止重复更新/恢复，保留诊断交由管理方核验；本记录中的一次性恢复路径也没有解决该拦截。当前源码修正见[本批次记录](GITHUB_CLEANUP_20261126.md)。

## 正确的升级起点

现有用户使用1.0.13或1.0.14，1.0.15未公开发布。最初验收误把起点写成14/15，已撤回该结论和旧修复工具，补齐真实原版13的验证，并将修复器内嵌白名单更正为官方13/14主EXE哈希。

## 实现

- 同一主EXE使用两种程序包：旧通道使用schema 1兼容包装及真实验证过的双协议worker；新版通道使用schema 2内置执行器。包和清单严格绑定，不降低精确文件白名单检查。
- 完整安装和一次性恢复后的安装不依赖独立worker；旧通道桥接安装有严格验证后的内置备用路径。
- 一次性修复器先核验旧EXE、固定程序ZIP、原配置和资料路径，正常退出原程序后执行原事务备份、替换、健康检查、原生窗口确认和提交；失败尝试恢复原版本。原资料及4B模型保持。
- 修复器源码和固定发布身份位于 scripts/recovery_1_0_16/。不猜测资料库，不接受替换信任清单，不关闭安全软件。

## 使用与上传

正常13/14：发布源更新后，软件内检查更新并重启，不用删除旧版或重新下载模型。

反复暂存缺件的13：保存编辑并导出备份，解压官方一次性修复ZIP到独立文件夹，保持EXE和配套Program.zip同目录（不要解压Program.zip），运行工具选择原PocketMemory.exe，核对版本与资料库后确认。成功后检查16、笔记及附件；不要手动覆盖_internal或清理事务备份。

COS先上传Program-Legacy.zip、Program.zip和完整PocketMemory-latest.zip，再上传PocketMemory-update.json与PocketMemory-update-v2.json。旧通道JSON只能指向兼容包，新通道指向schema 2包。私人资料、诊断日志和撤回工具不公开上传。

## 验证边界

日志证实暂存文件缺失，但没有直接证据确定外部移除原因。本机故障注入不等于覆盖企业终端安全策略，不能保证所有机器均不拦截。未改4B/RAG/汇编算法，未新增模型生成或全量问答回归。GitHub仅发布代码、测试及说明，不包含模型、EXE、私人资料或原始诊断包。
