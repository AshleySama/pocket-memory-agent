# 1.0.13 更新执行恢复与首次加载

本版保留原4B、RAG、资料汇编和主题；用户更新说明见[1.0.13](RELEASE_1.0.13.md)。

## 两项修改

- 独立更新组件确实缺失时，校验当前主程序、运行库和完整安装收据，复制到安装目录外，以内置入口执行原更新事务。损坏、不可读、未声明运行库等情况仍阻止升级；旧无能力声明安装不会被误当成支持备用路径。下载载荷仍必须含独立组件，兼容旧版更新协议。
- 页面关键脚本首次失败可有限恢复，样式和Logo有限重试；初始只读请求有超时与恢复提示。已输入或正在写入时不自动刷新，保存/导入/问答不会自动重发。桌面就绪需等待页面、笔记与草稿保护完成。

## 验证

- 复用依赖指纹相同的134项更新检查、63项启动及相邻行为检查、6组真实WebView2故障验证。
- 新跑18项交付/旧更新交接检查和3项主入口默认值保护。发布复核拦截了主入口默认汇编开关遗漏，恢复与1.0.12的main行为完全一致后重建主程序；允许显式0回退。该失误未进入最终交付。
- 最终1.0.13 EXE在隔离完整包中验证8场景：首次原生桌面完整就绪、缺组件启动、其他运行文件损坏拦截、真实1.0.12→1.0.13升级、新独立更新器事务、内置更新器事务、缺件载荷拒绝、无效新EXE自动回滚并重新打开原桌面。
- 事务前后核对笔记、附件、配置和原24项模型资源；回滚还核对原程序文件、安装收据和原缺组件状态。测试使用隔离资料库；没有运行模型生成。
- 正式完整包必须由离线交付流程生成完整installed.json，包含能力声明、主程序、Python DLL及独立更新器的哈希清单。原始构建目录/ZIP不等同于可发行的完整离线布局。

## 缺组件旧版如何升级

1. 保存笔记，记录设置中的原资料库位置，导出完整备份。
2. 从托盘完全退出旧程序，将新的1.0.13完整离线ZIP解压到新文件夹。
3. 运行新PocketMemory.exe，确认1.0.13，选择原资料库并核对笔记、附件和文稿。
4. 保留旧目录和备份，不要手工覆盖_internal或逐个补文件。仅复制EXE不能得到完整安装；保留隐藏的.pocket-memory-update安装记录。

已经缺组件的旧1.0.12无法靠旧更新按钮自行获得修复，需一次新的完整包迁移。1.0.12自带旧更新器没有内置能力；若它升级期间组件继续丢失，仍会拦截或回滚，不能用新版能力描述旧执行器。

## 边界

真实EXE事务使用本地受控更新载荷。新版独立/内置事务为同版本验证；1.0.12→1.0.13为真实版本迁移。未验证同事企业终端策略或本次公网下载按钮；尚无证据证明原组件由安全软件删除，不保证所有环境都允许执行。GitHub源码同步不会自动上传COS包。
