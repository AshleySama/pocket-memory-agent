# 1.0.12 更新完整性修复与验收

本次保留1.0.11的4B模型、问答、资料汇编及已有修复，更新说明见[1.0.12](RELEASE_1.0.12.md)。同步1.0.11已交付的汇编范围、表格行与状态字段处理到仓库；本轮没有重新调优这些功能。

## 修复

- 旧打包入口也强制构建并检查更新组件；完整包、更新包和安装收据使用同一组件清单。
- 安装启动、开始升级、更新载荷、替换完成、健康检查和提交事务均核对组件。组件缺失或损坏时停止自动升级；笔记仍可保存、备份和正常退出。
- 缺件状态显示完整包恢复步骤，不要求用户逐个补文件。不把失败的健康检查作为升级成功；原程序备份与回滚保留。
- 发布验收发现完整包的旧安装收据缺少manifest，会使新启动检查误报。本轮已修正完整包生成脚本，并增加“生成收据→启动读取→组件变更”契约检查。

- 主程序和更新组件各构建一次；完整包收据修正仅改变布局脚本和测试，不在两者的PYZ中，未重复编译。最终复核还统一了包内恢复说明；只改变README与对应清单/收据哈希，EXE、更新组件、其他程序和模型与上述验收逐字节一致。
- 最终EXE在隔离完整安装副本启动，实际原生窗口可见，安装清单检查通过。
- 移走组件后，启动和升级检查报告缺件，升级API拒绝；实际笔记保存/读取、完整备份下载和正常退出通过。原文件复位后重新启动检查恢复正常。

## 缺件旧安装如何升级

1. 保存笔记，在设置的数据页确认资料库路径并导出完整备份。
2. 从托盘完全退出旧程序，将本次1.0.12完整离线ZIP解压到新文件夹。
3. 运行新目录的PocketMemory.exe，确认1.0.12并选择原资料库，核对笔记、附件和文稿。
4. 保留旧目录与资料备份，不要零散覆盖_internal。缺组件的旧安装无法靠更新清单自行恢复，也无需单独领取组件。

## 验证边界

升级测试使用本地受控暂存包、真实Windows进程与原生桌面，没有模拟更新器业务函数。未测试公网下载按钮或同事企业安全软件；不承诺其他电脑不会隔离组件。GitHub源码推送不会自动上传COS安装包，旧下载链接在COS更新前仍可能指向旧版本。

本轮零模型生成；没有以更新链路检查宣称RAG或报告质量提升。旧程序包与资料备份保留。实际被测源与公开源只允许许可证注释差异；README图片、网站及不相关远端文件保留。
