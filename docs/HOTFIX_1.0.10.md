# 1.0.10 技术修复与验证

本次同步1.0.9已交付功能及1.0.10热修复；公开更新介绍仍保留[原定三条](RELEASE_1.0.10.md)。模型保持现有4B。

## 两项热修复

- **打包后的资料汇编无法生成**：旧实现为计算代码指纹直接读取`report_brief.py`。冻结程序可能只含PYZ字节码，导致生成前出现FileNotFoundError。改为从实际模块loader取得代码对象并计算稳定指纹，保留严格缓存及提纲契约，不再要求独立源码文件。旧缓存需要重新计算一次；历史成稿不删除。
- **更新交接ready.json临时拒读**：对短暂不存在或PermissionError在既定时间内重试，保留身份、token、链接和长度校验；只有go写成功才请求旧程序退出。持续权限错误仍安全失败。

## 已执行与复用的验证

- 两项对应的74+51=125项检查通过，冻结代码指纹与受测候选一致，复用结果，不重复跑全套问答。
- 复用1.0.9此前1292项通过/1项环境跳过的后端结果及21份前端检查，不称本版全部新跑。
- 最终Windows EXE经真实资料汇编API创建新稿，实际走`source_brief_v2`，现有Qwen3-4B调用1次19.672秒。三项风险和处理动作保留；3处引用逐字匹配原文；保存重开、HTML落盘及HTTP下载通过。该耗时仅为开发机单样例，不是目标机性能承诺。
- 独立安装副本本地受控1.0.9→1.0.10升级、原生桌面自动打开及退出通过；资料记录、配置、24项模型不变，2084项程序文件清单匹配。完整包与程序更新包CRC和SHA256校验通过。

## 边界与恢复

- 上述真实生成是单笔记一个有内容页签的冒烟，不代表多页签、所有提示词或复杂报告质量验收；已有双页签检查来自固定响应的冻结模块探针。样例仍带有部分背景文字，未据此宣称内容组织问题全部解决。
- 旧1.0.8/1.0.9自身的ready读取逻辑不会因下载新程序包而提前更新。若应用内更新仍报拒读，请退出旧程序，将1.0.10完整包解压到新目录启动，确认使用原资料库。保留旧目录和备份，不单独覆盖_internal。
- 本地受控升级不等于公网下载按钮或企业电脑权限环境验证。此Git提交不自动上传安装包或发布更新清单。
- 提交副本对缺少声明的项目源码仅补充许可证注释，Python AST及原正文保持不变；已打包冻结源未改。README保留最新宣传页和截图，原始问答、私人资料、模型和安装包不进入Git。
